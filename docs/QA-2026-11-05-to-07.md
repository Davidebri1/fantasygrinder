# QA record — Fantasy Grinder, week of 2026-11-05 → 2026-11-07

Every change below: symptom → cause → change → before/after. Verified on the live site by SHA256.

## 1. The app opened with 150 lineups already built
- **Symptom:** opening the optimizer showed finished lineups before any click.
- **Cause:** an auto-build effect keyed off the slate version rebuilt the portfolio on every load.
- **Change:** the effect is deleted. Nothing builds until the customer presses Build portfolio; the empty state says so in plain words.
- **Before:** app opens, 150 skeletons already built. **After:** app opens on a slate and an empty results tab that says "Nothing is built until you press the button."

## 2. Modelled salaries sat in the real Salary field
- **Symptom:** a derived number (projection × 150 + 800) displayed where a DraftKings price belongs; "(est.)" tags tried to soften it.
- **Cause:** the live layer fabricated prices to keep the solver's cap meaningful.
- **Change:** the real Salary column shows ONLY a DK price, else Pending/blank. Estimates moved to their own hideable "Est. salary" column. The solver accepts only real published prices; on a pool without them it refuses with a plain banner (PricesMissingBanner).
- **Before:** $6,900 (est.) in a field that means DraftKings. **After:** Pending, or the real $9,400.

## 3. Modelled ownership fed surfaces that could not act on it
- **Symptom:** "Own % (est.)" in the pool, drawer, stacks; a contrarian strategy built on a percentile.
- **Cause:** leverage strategy needed an opponent-overlap input no free feed publishes.
- **Change:** all modelled ownership sites removed; contrarian option hidden until real contest-entry data lands.
- **Before:** modelled crowd sizes presented as inputs. **After:** gone; the strategy list is honest.

## 4. The backtest violated the sample-size law and led with a selfish metric
- **Symptom:** 42-63% interval hit-rates built on 5-7 prior games per player; mean-absolute-error headline.
- **Cause:** the harness validated on any game with ≥5 earlier in-season games.
- **Change:** rebuilt over ESPN's full published history (2002→2026 for the 4 sampled teams), projections issued ONLY at ≥30 earlier games across the whole career (5,343 targets, 19,638 refused), headline is scenario metrics: booms called 49.2%, busts called 52.6%, direction 50.9% (baseline 50.7%) — McNemar z-tests shown.
- **Before:** CLT-violating histogram dressed as accuracy. **After:** n≥30 gate, honest refusal counts, actionable scenario rates.

## 5. Every deploy risked another authorization
- **Symptom:** deploy fails demanding re-login (badge in chat: "authorization each 2 seconds").
- **Cause:** wrangler's stored OAuth has two possible config roots and expired mid-day once; npx had also floated to a version that forbids non-interactive OAuth.
- **Change:** wrangler pinned 4.157.0; deploy script unifies both config roots automatically; proven with an unattended deploy (29bc82e2) hours after login, zero prompts.
- **Before:** deploy could die on auth. **After:** self-healing; the one-time Cloudflare token step remains queued for when Dave is on the tab.

## 6. The seed
- The bundled DraftKings JAX@BAL showdown loadable slate (real prices, DK's own projections, DK photos) ships in the build so the app opens WITH data on screen and an empty portfolio awaiting the customer's choice.
